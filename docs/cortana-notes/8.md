## Key architectural difference

**joryirving/home-ops** runs local models on **Strix Halo (256GB unified) + RTX 3090 (24GB)** — two separate machines with different architectures.

**Your DGX Spark** runs on **GB10 (Grace CPU + Blackwell GPU, 128GB unified)** — one machine, arm64, much more memory per node but different GPU architecture.

The Qwen3.5-397B-A17B is **significantly more capable** than the current flash-next (180B/6B vs 397B/17B), but it's also heavier. The 17B active params means it uses more compute per token than flash-next's 6B, so throughput may be lower even though quality is higher.

## Summary

- **Primary local model**: qwen3.5-397b-int4 is a **direct drop-in replacement** for qwen3.8-flash-next — bigger, better, same MoE architecture
- **Embedding/reranking**: These run on **CPU nodes** (not DGX). You'll need to keep deploy them on a CPU node or use cloud APIs
- **Vision**: Verify if the Qwen3.5-397B model includes vision capability (the base Qwen3.5-397B-A17B is text-only; vision would need a separate VL model)
- **The 37 recipes**: Most are drop-in replacements for the cloud subscription models they're configured to replace (MiniMax, GLM, Kimi, etc.) — they just run locally instead of via LiteLLM subscriptions
